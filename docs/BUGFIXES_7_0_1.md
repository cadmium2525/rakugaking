## 版と既存データ

アプリ表示・パッケージは **7.0.1**、タイムとオンラインランキングのルール版は **7.0.0**、保存形式は **4**。コースと能力の比較基準を変更していないため、既存の有効な7.0のタイム、キャラクター、EXP、解放状態、設定を引き継ぐ。6.0以前のタイムを旧記録へ退避する7.0の扱いは維持する。

新しい保存にはベストの完全な記録とそのルール版を追加する。修正前の保存にベストの数値しか残っていない場合も、7.0.0の記録と判断できるものはその数値を保持する。残っていない走行の内容を、別の遅い記録で補って復元したことにはしない。ルール版不明・旧版・異常な記録を現在のベストとして採用しない。[実装](../src/core/records.js) / [記録の回帰テスト](../tests/records.test.js)。

## 関連する追加対応

「誕生させる」は保存結果を待ち、失敗した場合は編集画面と下書きを残す。同じ未保存キャラクターの再試行で仲間が重複しないようにした。保存待ちの間に閉じて開き直した別の下書きや、その間に描き足した線を、古い保存の完了によって閉じない。保存開始時の絵と、その後の未保存の絵を区別する。[ブラウザ回帰](../tests/browser/editor-recovery.spec.js) / [保存競合時の下書き](../tests/browser/save-conflicts.spec.js)。

誕生保存が失敗した後、音設定など別の操作の保存にその子が含まれて成功した場合も、未保存状態を確定する。先に待機中の保存結果を確認してから次の誕生を処理し、同じ編集セッション内の再試行だけが未保存の子を再利用する。保存の試行も区別するため、古い保存の完了で新しい試行の状態を解除しない。次の編集で作った別の子が、以前の子を上書きしないことを実ブラウザの保存・再読込みで確認した。[誕生と保存処理](../src/game/app.js) / [別操作の保存完了後に次の子を作る回帰](../tests/browser/editor-recovery.spec.js)。

LAN内のHTTP配信で `crypto.randomUUID` が存在せず、保存処理の生成時点で起動できない条件にも対応した。キャラクター・ローカル走行・保存識別のためのIDは、使用可能な暗号API、または端末内用の補完生成を使う。公開ランキングの認証トークンには使わない。単体5件でAPIの有無・例外・同時刻・保存の再読込みを、実ブラウザでUUIDとWeb Locksのない条件の起動・誕生保存・再読込みを確認した。[端末内ID](../src/core/local-id.js) / [単体](../tests/local-id.test.js) / [ブラウザ回帰](../tests/browser/save-conflicts.spec.js)。

名前の途中にあるタブなども、エディタで保持される文字列のまま端末内の記録に残す。公開ランキングの名前条件は緩めていない。結果画面からのランキング送信は、履歴の最後ではなく今回の完走結果を参照する。今回の結果が履歴の検証で除外されても、以前の走行を送信対象として選ばない。[記録処理](../src/core/records.js) / [結果と保存処理](../src/game/app.js)。

## 保存の条件と残る制約

IndexedDBを優先する。Web Locksがない環境でも、IndexedDBが利用できれば同一トランザクション内で照合と書込みを行える。localStorageへの代替保存にはWeb Locksによるタブ間の直列化と、書込み直前の再照合が必要である。Web Locksも利用可能なIndexedDBもない場合、本体への保存を止めて通知し、下書きの別バックアップを試みる。

設定されているIndexedDBを読み込めず、その中に新しい保存がないと確認できない場合も、localStorageだけを見て本体を上書きしない。初回読込みから利用不能な場合を含む。画面に保存状態を確認できない旨を表示し、読込みが復旧した後の再試行で改めて照合する。[保存実装](../src/core/save.js) / [安全な代替保存と読込み不能の回帰](../tests/save.test.js)。

別タブの更新を検出したタブは、その後も本体への上書きを停止する。未保存のキャラクター・進行・設定は別のバックアップへ退避し、退避不能なら現在のアプリ内にだけ残す。**自動統合とバックアップの復元画面はない。** 警告が出たタブの下書きを残し、最新データは新しいタブで確認する。ページを閉じたり再読み込みしたりすれば、画面内だけの下書きは失われる。バックアップがあっても、通常の起動で自動復元されるとは扱わない。

保存競合の保護は、7.0.1を起動したタブ同士を対象とする。旧7.0のキャッシュで開いたままのタブは新しい照合処理を使わず書き込めるため、そのタブの上書きまで制御したとは扱わない。更新時は下書きを保存して旧版のゲームタブ・PWAを閉じ、7.0.1で再起動する。

匿名ランキングIDを永続保存できない場合、現在のページ内では同じIDを使うが、再読込み後も同じIDであるとは保証しない。公開ランキングの本番接続、iPhone/Android実機操作、端末ごとの容量・データ削除条件は未検証のままである。
