# ステージ2〜5のフィールド改善の比較記録

2026-10-04、改修したローカル開発版を Edge / ソフトウェア WebGL で確認。保存データには通常の既クリア履歴だけを与え、位置・ミッション・HPは書き換えず、WASD、カメラ旋回、タッチスティックを使った。

## 確認できた改善

- 全ステージで開始地点、西の丘、中腹、東の丘までジャンプなしで移動。看板や細い柱によるカメラの急接近、大看板による画面遮蔽は発生しなかった。
- ステージ2は麦丘から谷・橋・風車・灯台を見渡せる。ステージ3は大水道の梁と支柱の接続が揃い、低地の水路と蓮の庭を横断できる。
- ステージ4は南側から街区の外側を歩いて西の丘へ上がり、建物に塞がれず中央へ回り込める。ステージ5は月庭から尾根の柱廊を通って北の城裏へ歩ける。
- ステージ5の新回廊ではHPのかけらを2個拾える。未達成のまま城裏からゴールへ入ってもクリアせず、報酬も得られない。
- 390×844と844×390の両方でタッチスティックによる実移動を確認。主要操作とHP表示は画面内に収まる。
- 全4ステージで pageerror / console.error / 死亡は0。

## 第2改善までに残った弱点

- 全周の透けたフェンスは見通しを遮らないが、遠景の四角い人工境界を強く意識させる。
- 各テーマのランドマークは変わったものの、開始地点から左右のミッション地区と北のボスへ向かう構図は共通している。
- ステージ4の公園は緑の丘の印象が強く、街の公共空間としての特徴は弱い。家も単純な箱形が中心。
- 雲が薄い円盤に見え、空の質感が乏しい。ステージ5の星や雲海も控えめ。
- 開いた地面には空白があり、主ミッション以外の発見はHPのかけらが中心。広さだけで探索の面白さが十分に成立したとは判断しない。

この段階の画像20枚をローカルで保存し、代表画像を `before/` に残した。独立批評はゲーム全体を76/100と評価し、近接遮蔽とステージ4の固有の見どころ・外周の単調さを次の改善条件にした。

## 検証結果

この段階の `node --test tests/field-space.test.js tests/expedition.test.js` は34/34成功。重い体と軽い体の周回、道外の横断、最大ジャンプによる外周脱出防止、回廊と北ゴール、通常のミッション完走を含む。従来の高い外周を足場に使う屋根到達試験は、接触と脱出を確認する局所衝突試験へ変更した。屋根へ現在の通常経路で登れるという主張はしていない。

追加改修前の地域画面における描画量は、ステージ2が61 calls / 75,010 triangles、3が53 / 74,722、4が66 / 78,474、5が59 / 76,450。影を含むブラウザ上の計測であり、スマートフォン実機の性能はこの確認から判断できない。

## 第3改善の確認

公園に噴水・ベンチ・花壇・樹木と連絡道を追加。散策が既存のHP2個を巡る外周ルートへ繋がる。障害物は共通データから実衝突と描画を作り、噴水の石の縁も身体を止める。雲は5つの低ポリの塊を既存のインスタンス群に追加して立体化した。

外周は主要144×136mを内包する23頂点の不規則な線へ変更。透明な矩形の境界は使わず、見えるスラットと実colliderを同じ位置に置いた。35/35件のテストが成功。重い体と軽い体の両方で、各頂点と各辺の中点の全46地点へジャンプを繰り返し、全フレームで実境界内・地形上に留まることを検証した。公園にも実徒歩で入り、噴水との衝突、脱出、既存の2個のかけら取得と周回を確認した。

最新版のブラウザ撮影は完了。`field-{2..5}-{start,west,middle,east}.png` の16枚、モバイル2枚、尾根回廊・北側未解放ゴールの2枚を上書きし、海側、水路、噴水公園、噴水公園の横画面を追加した。合計24枚。追加改修前の代表画像は `before/` と比較できる。

撮影中、36,-53から53,-42へデジタル斜め移動すると、Zを先に合わせた最後の東向き移動がベンチに当たる問題を発見した。ベンチを49,-42から49,-40へ移し、実キー操作で同じルートを通って公園を周回することを確認。公園テストを両型×連続方向/デジタル方向の4ケースへ広げ、成功した。噴水内のランダム小石と花壇の花の高さも修正し、最後に4の開始・東丘・公園近景・横画面を再撮影。全4ステージでpageerror / console.error / 死亡は0。北側ゴールの未解放状態も再確認した。

観測ファイルの範囲を区別する。`field-runtime-observations.json` は第2改善の元の全4ステージ記録で、追加改修前のもの。第3改善の2/3は最初の分割撮影で完了したが、次の4の停止で一括JSON出力に到達しなかった。実行ログに残る東丘の描画量は2が62 calls / 80,018 triangles、3が53 / 79,714。`field-runtime-observations-after-landscape.json` はベンチ修正後の4/5の再撮影だけ、`field-landscape-observations.json` は最後の公園仕上げ後の4の短い再撮影だけである。未観測の最終位置や値を復元していない。

4の東丘ではベンチ修正後81 calls / 88,750 trianglesを観測し、最後の公園から開始地点へ戻った画面は171 / 97,124だった。5の東丘は59 / 81,466、城裏の近接画面は50 / 80,646。位置・視点で描画量が変わり、公園の画面は追加前より描画量が増えている。ブラウザ上の表示・実入力確認であり、スマートフォン実機の速度は評価していない。

柵の折れ方は控えめで、箱庭として囲われた印象は残る。公園は小規模な寄り道で、探索を大きく変える新ミッションではない。雲も低ポリの表現の範囲に留まる。正式な合否・採点は新しい独立批評の実操作結果に委ね、装飾数や境界の頂点数を加点の根拠にはしない。
